# Native numeric field editing — #316

The shared interpreter/controller and injected extension now support explicit `set Quantity number field to 3`, `change number field to -0.25` and `undo Quantity number field`. Native number fields retain their existing roles and ordinary dictation; explicit numeric intent is isolated through a native descriptor and owned snapshot. This advances real-page form completion without claiming physical speech/gaze or intended-user acceptance (#132).

Native min/max/step admission occurs on a detached control before live focus or events. Input literals remain strings, preventing JavaScript decimal coercion from silently rewriting digits; the website's native numeric validation still uses browser precision. The target must retain type, document/root/frame/form ownership, name, constraints, default-value step base and current value through focus. Current visibility and native/ARIA/inert ancestor locks apply. One native setter emits input/change with ordinary propagation, then feedback checks retained state after website microtasks. No implicit submit, custom ARIA spinner scripting, number-word/unit conversion or forced website state.

Numeric history belongs to the exact element and is bounded separately from text/slider history. Writes retain prior literal field values even when website handlers temporarily roll them back. Undo can restore a previously empty required field; other earlier values must fit current numeric constraints. No-op set does not push; already-restored Undo consumes its entry. Per-element numeric revisions prevent a deferred Undo refusal from reinstating an obsolete entry after a newer numeric command. Replacement nodes inherit no history.
