# Clothing saved-design library — #295

The user outcome is returning to multiple complete garment designs or named versions from the 3D workspace. Current autosave holds one concept. Add a small explicit library without narrowing the full professional garment-design vision or changing its physics/fit claims.

Use an immutable named-copy model: Save named copy captures the currently committed Project, and later edits never update it. Names contain1–80 trimmed printable characters and are unique case-insensitively; use a new name for a new version. At most12 copies, each at the existing6MiB serialized-project limit. These are implementation bounds, not permanent vision limits. No overwrite/rename/automatic startup restore/cloud sync is included; delete a selected old copy deliberately after downloading its backup if desired.

Use a separate IndexedDB `clothing-studio-designs` version1 with `metadata` and `payloads` stores. Metadata `{id,name,savedAt,bytes}` is small and listed independently of full payloads. Payloads are ordinary validated serialized Project JSON keyed by the same UUID. Add and delete both stores atomically; readwrite transactions recheck the current metadata set for capacity/unique names. Every operation has a bounded open/transaction deadline, closes connections, and waits for native transaction completion/rollback before reporting. A blocked/failing/corrupt record is reported without clearing data. Metadata is validated, selected reads/deletes compare the captured metadata receipt, and reads verify payload byte count/project/media. No existing autosave schema/database is migrated.

Add Saved designs as an existing workspace-managed secondary dialog. Its mounted controls retain the name draft on closing/navigation. Refresh lists metadata, preserving an existing current selection without automatically choosing another. Save captures its name/project before async media validation and may complete while newer editing continues; it never applies a design or overwrites newer name input. Open selected design validates existing raw product/concept/pattern/grading/body fields and gestures, confirms replacement, then uses the same owned load-generation path as Open backup. Newer edits/imports/history/pagehide retire it; late completion cannot apply. Successful opening is one history step, resets construction/product views and follows current autosave protection. Download selected backup captures that copy independently of current design. Delete confirms its selected name and deletes only its exact metadata/payload receipt; it cannot affect current work.

The module boundaries are pure metadata/name validation and IndexedDB persistence, a mounted view with injected current/guard/open/download callbacks, and a small main/workspace integration. Existing project validation, image admission, draft handling and import ownership remain authoritative.

Acceptance covers complete graph round-trip, two independent designs and version names, native reload, exact JSON downloads and one-step Undo/Redo; duplicate/cap/concurrent writes; invalid/quota/blocked storage preservation; stale receipt/late open retirement; current raw drafts and private photo/motif bytes; actual390px and keyboard dialog focus. Automated software checks do not establish physical manufacture, calibrated materials or intended-user usability. JSON backups remain important because browser storage can be cleared.
