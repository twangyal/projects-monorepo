# Correct words in automatic review — #253

## Outcome and design

Automatic karaoke should need efficient correction rather than supplying all lyrics. The review already auditions captured recognized timings, but users previously had to apply incorrect words before editing. Editable staged words now connect listening and correction directly. This bounded milestone retains recognition timing/confidence separately; original words remain in an expandable detail. Timing and cue split/merge still use the existing main editor after Apply.

Filtering and opening the same live review preserve staged words. A separate text vector retains even invalid text without mutating transcript or working cues. The existing full cue validator admits all staged lines, including hidden ones, before Apply. Its errors are visible outside the scrolling/filter list. Invalid review text blocks Apply while captured recognized audio remains available. Existing 240-code-point/line and 20,000-total limits remain enforced, without silently truncating text. Apply revalidates and records the exact prior native editor snapshot as one undoable unsaved edit. Cancel/replacement clears only reviewed text. Busy work disables review input. No backend, schema, model, dependency or security change.
