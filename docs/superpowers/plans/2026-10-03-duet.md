# Duet Implementation Plan

> Agentic workers use executing-plans with fixed ownership and fresh final review.

**Goal:** Deliver issue #18's genuine two-participant music room with persistent preferences, synchronized listening and song memories.
**Architecture:** SQLite-backed domain, strict loopback HTTP/media jobs, bounded real FFmpeg normalizer, browser audio synchronization, TypeScript/Vite workspace.
**Tech Stack:** Python 3.11+ standard library, FFmpeg, TypeScript/Vite, native audio, Playwright.
**Spec:** `docs/superpowers/specs/2026-10-03-duet-design.md` defines exact shared APIs, payloads and bounds.

## Constraints and review focus

Five rooms, two participants per room, twelve tracks per room, and one hundred memories per room. Uploads are limited to 25 MiB and 300 seconds; canonical media to 8 MiB. One job at a time, 64 KiB JSON requests, a 45-second worker limit, and 512 MiB RSS. Private capabilities are hashed at rest; tokens never appear in media URLs, exports, or logs. Mutations use bearer authentication and Origin checks; native audio reads use a scoped HttpOnly Strict cookie. Acquire the directory lock before cleanup.

Focus tests on concurrent join/command conflicts; unauthenticated audio/room access; consumed invitations and cross-room leaks; stale metadata/play promises; persistence/cancellation; and blocked-autoplay recovery. Real browser drift measurement proves only the same-machine protocol, not arbitrary network performance.
