# Learned screening paraphrase experiment

**Outcome: unavailable.** This preregistered trial for [issue #36](https://github.com/twangyal/projects-monorepo/issues/36) failed development readiness. The application does not import these files and retains its precise query grammar. No held-out inference was run, and the two proposed new grammar shortcuts were not added.

The genuine local multinomial logistic model fitted 180 original authored phrases, using binary unigram/bigram TF-IDF, 534 fitted features and 41 solver iterations. Under the frozen unsupported-request policy and 1,287-point threshold grid, no candidate achieved any supported acceptance while meeting the zero-error and zero-unsupported-acceptance constraints. The selected diagnostic candidate accepted **0/60 supported development phrases**, including 0/10 in each class. With zero accepted phrases, accepted-output accuracy is undefined; model convergence and correct arithmetic do not establish useful interpretation.

There is also a benchmark admission failure: the 80 raw unsupported development rows include 79 printable-ASCII language requests and one Unicode-format input. That leaves fewer than the required 80 admissible unsupported language cases. The strict checker rejects this corpus. Its bytes were preserved once development outcomes had been observed; the separate diagnostic mode reports this limitation and cannot authorize release.

Independent standard-library inference agrees with all 140 reference development rows, with zero decision/mapping mismatches and maximum absolute numerical error `2.7755575615628914e-16`. The [diagnostic report](development-diagnostic.json) explicitly records `diagnosticOnly: true`, `benchmarkAdmissible: false` and `developmentReady: false`. The model is 115,562 bytes; model and corrected development report regenerated byte-for-byte in separate fresh processes. The 31 persisted synthetic tests cover reference/trainer correctness and independent evaluator safety without importing scientific packages. CI runs those tests and the failed-trial diagnostic; green implementation checks do not mean the model passed its release gate.

## Protocol and provenance

The [reviewed design](../../../../docs/superpowers/specs/2026-10-04-stock-paraphrase-gate-design.md), [training contract](training-contract.json) and [evaluation contract](evaluation-contract.md) define six single-intent English mappings, exact whole-screen defaults, preprocessing, rejection rules, training math and release criteria. The mappings cover positive/negative net income, positive/negative revenue growth, low debt/equity and high net margin. They are not financial analysis, a general language model or calibrated correctness probabilities.

Separate authors supplied training/development data and the 120 supported/170 unsupported holdouts. An independent reviewer read all 610 raw requests and audited labels and phrase-family overlap without model feedback. Pre-fit construction, strict-sign label and deterministic-policy conflicts were corrected and recorded in [corpus-audit.json](corpus-audit.json). Its broad static schema review did not establish the stricter development benchmark admission subsequently checked by the evaluator. The later Unicode admission finding is preserved as failed evidence. Corpora, policy, fitted weights and thresholds were not changed after development outcomes; only contract-required numerical accumulation and producer/evaluator interface correctness were repaired before recording the final diagnostic.

The trainer did not read held-out files, and the evaluator did not open them. They remain unused in this trial. The originally required release gate was at least 15/20 accepted supported examples per class, at least 98% exact-screen accuracy among accepted examples, and no accepted unsupported example. Development readiness was a prerequisite, so that gate was never opened. A future attempt needs a separately reviewed protocol and fresh independently authored holdouts; these published data are retained for reproducibility, not a generalization claim.

[trial-manifest.json](trial-manifest.json) records exact file hashes and the failed status. No product UI integration, financial recommendation, remote inference, paid service or downloaded model is involved.

## Reproduce without fitting dependencies

From `apps/stock-notebook`:

```sh
python3 -S -B -m unittest discover -s experiments/paraphrase -p 'test_*.py'
python3 -S -B experiments/paraphrase/evaluate.py --diagnostic-development \
  --artifact experiments/paraphrase/model.json \
  --development experiments/paraphrase/development.json \
  --parity experiments/paraphrase/development-results.json \
  --output /tmp/stock-paraphrase-diagnostic.json
```

The diagnostic exits zero when all reference math agrees, while explicitly keeping the benchmark invalid and readiness false. `--check-development` with the same inputs instead exits 2 because of the Unicode-format row. The normal release command checks readiness before opening any held-out file; do not run it for this failed trial. Synthetic safety tests do not read the real holdouts.

## Regenerate the fitted diagnostic artifact

The fit requires exactly Python 3.12.14 and the versions in `requirements.txt`, already available in the implementation environment. They are not application or CI dependencies. From this directory, use a new temporary output directory:

```sh
paraphrase_output_dir="$(mktemp -d)"
python3 -B train.py --model-output "$paraphrase_output_dir/model.json" \
  --report-output "$paraphrase_output_dir/development-results.json"
cmp model.json "$paraphrase_output_dir/model.json"
cmp development-results.json "$paraphrase_output_dir/development-results.json"
```

The trainer fixes its random seed and numeric thread counts before imports, checks dependency versions, fits vocabulary/IDF on training only, and records the entire development grid. A successful training command can still report `notReady`; do not interpret process completion as release approval. Scientific-library behavior on other platforms remains a reproducibility limit even with pinned versions.
