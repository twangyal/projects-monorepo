# Committed JavaScript and TypeScript function selection

Issue [#34](https://github.com/twangyal/projects-monorepo/issues/34). Extend the existing local Git evidence explorer to the monorepo's principal source languages. Existing Python selection, manual ranges, immutable snapshot resolution, evidence, output protection and dependency-free installation remain intact. No source execution, repository configuration reads for parsing, network calls or model downloads.

## User behavior

The optional `javascript` extra pins `tree-sitter==0.25.2`, `tree-sitter-javascript==0.25.0` and `tree-sitter-typescript==0.23.2`. Missing or incompatible packages fail with installation guidance and the manual `--lines` fallback. `.js`, `.jsx`, `.mjs`, `.cjs` use JavaScript grammar; `.ts`, `.mts`, `.cts` use TypeScript; `.tsx` uses TSX. `.d.ts` parses normally but declarations without implementation bodies are omitted. No package.json or tsconfig is loaded. Python `.py`/`.pyi` still uses stdlib AST; manual ranges load no native parser.

`functions` lists original committed physical source ranges and exact qualified names. `explain --function` uses existing unique-name selection and the same once-resolved commit for all evidence. Duplicate names, including getter/setter pairs and static/instance collisions, remain ambiguous and require `--lines`. The 200-line explanation limit is unchanged; larger functions remain listed. No new JSON schema or function-name selector syntax is introduced.

## Syntax contract

- Include named function/generator declarations, ordinary or async, and direct identifier-bound arrow/function expressions. The external binding overrides an internal function-expression alias. Named default declarations retain their name; anonymous default exports are omitted.
- Include identifier-named class declarations and direct identifier-bound class expressions as scopes (not callable entries). Include body-bearing identifier methods, constructors, getters/setters and callable class fields. A bound class expression uses the external name. Accessors use the ordinary qualified name and kind `getter`/`setter`; other callable kinds are `function` or `async function`.
- Include identifier-bound object literals as namespaces, recursively through identifier properties. Their identifier methods and directly bound arrow/function values are callable entries. No runtime alias or assignment inference. Nested named classes/functions retain enclosing supported syntax scopes.
- Omit computed, private and string-literal property names, unbound callbacks, assignment right-hand sides, anonymous classes/functions and overload/interface/ambient signatures without bodies. TypeScript namespace/module bodies, class static-initializer blocks and functions inside parameter expressions are also omitted. Unsupported callable, class, object namespace and TypeScript namespace/module nodes are traversal barriers: their children must not be flattened into an enclosing qualified name.
- Transparent wrappers are limited to parenthesized expression, TypeScript `as`, `satisfies`, type assertion and non-null expression nodes. Only the expression child is traversed. Their associated callable binding range includes the wrapper; type nodes never supply function entries. Unsupported wrappers remain omitted. Binding/property names preserve exact identifier spelling, including escapes; no runtime identity or Unicode escape normalization is claimed.
- Function declarations include a direct enclosing export prefix. Bound expressions cover their own variable declarator/property/class field, not an unrelated multi-declarator statement. A separately lined `const` can therefore fall outside the range. Methods include attached method decorators and modifiers, never class decorators. TS sibling decorators attach only to the next member, allowing comments but not crossing a different member. Whole physical lines can include neighboring syntax on the same line.
- Derive inclusive 1-based line ranges from ORIGINAL UTF-8 byte offsets, counting LF only and using `end_byte - 1` for the final line. Preserve BOM, CRLF and Unicode line separators. Reject invalid UTF-8, NUL and any error/missing-node recovery tree. No partial catalog on syntax errors or resource limits.

## Isolated parser contract

Native parsing runs in a fresh POSIX subprocess: current Python with `-I -B`, a fixed trusted absolute worker entrypoint and trusted application cwd; the selected source is sent only on stdin. The child applies 512 MiB address-space, 3/4-second CPU, zero core and zero file-output resource limits before importing native dependencies. It reads at most 512 KiB plus one byte, decodes strict UTF-8 and uses iterative traversal. Native extensions and grammars are never loaded in the parent. No repository path enters the worker argv or import path.

The parent enforces a five-second wall deadline and eight MiB combined stdout/stderr while concurrently writing bounded stdin and draining output using nonblocking POSIX selectors. Timeout, output overflow, caller interruption (including KeyboardInterrupt/SystemExit), malformed replies, nonzero exit or unsupported isolation fails actionably; kill the process group and reap the child. Do not depend on Tree-sitter's ignored byte-input progress callback. Unsupported platforms fail rather than run unbounded.

Limits remain 512 KiB source, 10,000 entries and two MiB total UTF-8 qualified names. Worker output is a strict JSON protocol: either `{ "functions": [{ "qualified_name": ..., "start_line": ..., "end_line": ..., "kind": ... }] }` or `{ "error": CODE }`, where CODE is `dependencies`, `syntax`, `complexity` or `unsupported`. No source excerpts or native stderr are repeated in user errors. Parent validates exact keys, types (excluding bool-as-int), allowed kinds, name bounds, finite integral coordinates against LF-only source length, total names/count and strict JSON. Resource/protocol errors provide `--lines` guidance. Existing Python parser limits and exception behavior remain unchanged.

Implementation interfaces: `native_syntax.parse_native(source: str, language: str) -> list[FunctionDefinition]`, raising `NativeSyntaxError(code)` with a `.code` attribute from the fixed error-code set; `native_parser.parse_native_functions(source: str, language: str) -> list[FunctionDefinition]`, raising `NativeParserError(ValueError)` carrying sanitized actionable text. `function_parser.parse_functions` dispatches exact suffixes lazily and translates that error to its existing `FunctionParseError`. A small shared `native_protocol.py` owns limits/language/kind constants. Worker maps errors into the fixed codes above; implementation owners coordinate precise error attributes before edits.

## Evidence and completion

The pinned dependency/API gate passed on actual Linux Python 3.11.16, 3.12.14 and 3.13.5. macOS-compatible wheels exist but runtime has not been verified there. A 512 KiB stress fixture parsed/traversed in 0.20–0.24 seconds; deep malformed input peaked near 176 MiB RSS. These measurements inform bounds, not promises for arbitrary sources.

Required verification: syntax fixtures for the supported/omitted forms and range rules; independent expected qualified names/line numbers; malformed and oversized source; subprocess timeout/output/exit/schema/cancellation tests; real committed JS/TS repositories with dirty working trees, renamed paths, moving refs, duplicate names, >200-line selections and manual-range equivalence; dependency-free fallback and installed-wheel checks. Run the full existing suite plus optional-extra tests, Ruff/compile/build, and CI on Python 3.11–3.13. Exercise actual CLI HTML/JSON against allowed committed monorepo sources. Document exact installation/syntax/platform limitations and measurements. Commit/push, check CI and close #34 only to actual completion, then reassess.

Pinned grammar exception: bare `export` followed by a newline and a named function can parse as adjacent export-identifier expression and declaration nodes. A narrowly tested adjacency rule includes that prefix only when the preceding statement is exactly the bare export identifier, allowing comments but no semicolon or intervening statement. This does not claim full JavaScript semantic validation.
