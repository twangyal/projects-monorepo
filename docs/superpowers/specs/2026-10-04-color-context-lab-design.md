# Color Context Lab — bounded comparison and preregistered context experiment

Issue [#70](https://github.com/twangyal/projects-monorepo/issues/70), catalog idea10. New independent app: `apps/color-context-lab`. Reviewed and frozen by root and both independent reviewers. Application implementation is released after this design commit; protocol-model fitting still requires the separate committed generator/manifest receipt below.

## Outcome and claims

An artist can import a PNG, compare the same normalized artwork within neutral and chosen surrounds, inspect numerical differences, download exact PNGs and a complete editable project, then reopen it. A separate research panel presents one real, frozen procedural shape-classification experiment with controls and a preprocessing bypass. It does not run a model on uploaded artwork.

The first transform is surrounding context only: solid or two-color checker surround. The artwork rectangle remains byte-identical RGBA. This is deliberately not a promise of protection, perceived similarity, style disguise, training resistance or transfer to generative models. There is no generated image, pretrained model, remote source, paid API or network inference. Numerical encoded-sRGB differences are not human-perception measurements. Real human appearance judgments and artist/generative-model datasets remain future research.

“Normalized original” means the first bounded, orientation-free browser-decoded sRGB Canvas pixel raster retained in this project. Browser decoding/color conversion, premultiplication and optional downsampling can change encoded-file pixels. The original compressed upload is not retained; tell the user to keep it. Once captured, normalized RGBA is retained exactly through history, backups and all source/result PNG exports. Presentation Canvas may quantize low-alpha colors; PNG export never reads presentation Canvas pixels.

## Pixel kernel and metrics

For artwork size(w,h), border b yields W=w+2b,H=h+2b. Artwork occupies integer `[b,b+w)×[b,b+h)` and copies all four source bytes verbatim. Every other result pixel has alpha255. Solid uses colorA. Checker uses colorA when `(floor(x/cellSize)+floor(y/cellSize))%2===0`, else colorB; grid origin is full output(0,0). Baseline uses the same dimensions/artwork placement and solid RGB(128,128,128), alpha255 outside the artwork. With b=0 both outputs equal source exactly regardless of surround settings. Transparent artwork remains transparent; checkerboard shown behind preview canvases is presentation only and is never exported.

Metrics compare these exact two rasters, not the encoded source file. Artwork changed count considers any unequal RGBA channel inside the center; max delta there covers RGBA and must be zero for this transform. `surroundPixels=W*H-w*h`, `totalPixels=W*H`. `rgbRmse=sqrt(sum((resultRGB-baselineRGB)^2)/(3*W*H))` in encoded-sRGB byte units0..255; maxRgbDelta is the maximum absolute RGB byte difference over the full canvas. No alpha weighting: center RGB is identical, so all contributions are opaque surround pixels. Zero surround yields all differences zero.

Relative luminance is computed only from byte RGB: s=c/255; linear(s)=s/12.92 when s<=0.04045 else `((s+0.055)/1.055)^2.4`; Y=.2126R+.7152G+.0722B. meanAbsoluteLuminanceDelta is mean abs(Yresult-Ybaseline) over all W*H pixels, dimensionless0..1. This is a defined numerical diagnostic, not a perceptual distance or visibility threshold. Keep full finite numerical values in reports; UI may format them but never treat a rounded zero as proof of unchanged whole-canvas pixels. Do not calculate a protection score.

## PNG admission, normalization and exact exports

Producer2 owns `png.ts`, `images.ts`, `render.ts`, `jobs.ts`, `image.worker.ts`, `report.ts`, corresponding unit/native image/job harness tests. Root supplies pngjs solely as an independent test decoder; no runtime codec dependency.

PNG-only upload: File nonempty<=8 MiB; MIME empty or image/png; signature, complete chunk framing/CRC, exactly one first IHDR, nonempty consecutive IDAT group and terminal zero-length IEND with no trailing bytes. Admit8-bit truecolor RGB/RGBA (color types2/6), compression/filter method0 and noninterlaced only. Reject animation chunks, eXIf orientation metadata, unknown critical chunks, invalid/oversized dimensions and ancillary total>256 KiB (sum of each ancillary payload length plus its12-byte chunk framing/CRC) before native decode. Only IHDR/IDAT/IEND critical chunk types are admitted; PLTE is unsupported in this narrow truecolor subset. Chunk type bytes must be ASCII letters with the reserved third letter uppercase. Indexed-color/grayscale/high-depth/interlaced/animated PNG, JPEG/WebP/SVG/GIF are unsupported with actionable PNG conversion guidance. Chunk structure/CRC admission does not pretend to validate compressed pixels; actual browser decoder must succeed. Ancillary color metadata may influence that decode; no original encoded-color equivalence is promised.

Use createImageBitmap with orientation none and browser default color conversion, then sRGB OffscreenCanvas, smoothing high. Let f=min(1,720/max(sourceWidth,sourceHeight)); normalized dimensions=max(1,round(sourceDimension*f)). Verify native decoded dimensions match header before draw. getImageData defines the retained normalized RGBA; close ImageBitmap and zero Canvas in finally. Native decoding may not abort internally, but retired/terminated worker output can never publish. Do not normalize an already saved raw-RGBA asset again.

Exact PNG encoder emits signature, IHDR8-bitRGBA, sRGB rendering intent0, lossless stored-DEFLATE IDAT with correct Adler32, CRC per chunk, IEND; no ancillary source metadata. Encode raw result bytes directly, including low/zero-alpha RGB; PNG size<=4 MiB. At maximum976² pixels, stored RGBA/filter/DEFLATE/chunk overhead fits this cap. Read-only independent decoder compares every exported RGBA byte; Canvas readback is not this oracle.

## Preregistered procedural experiment — protocol v1

This is a controlled shape-recognition shortcut experiment, not artwork protection. Train a real small multiclass linear learner on original32×32 RGB fixtures. A deliberately label-correlated surround may change a model's decisions while leaving foreground pixels identical. Labels are geometric shapes, not artist identity/style. Randomized surrounds and removal of the known surround test the explanation and one obvious bypass. Null/negative effects remain valid results; no sensitivity threshold is a release gate.

Dependencies are separate pinned offline experiment requirements: Python3.12, NumPy2.3.5, Pillow12.3.0, scikit-learn1.8.0, SciPy1.17.0 (installed locally). Do not modify other projects' environments. No pretrained weights, downloads, artist corpus or Stock#36 artifacts. Record Python/platform/library versions and numeric/thread environment. All random generation uses numpy.random.Generator(PCG64(seed)); no implicit RNG/global clock dependence.

Dataset fixed before fitting:
- Four equally frequent classes0 horizontal bar,1 vertical bar,2 cross,3 disk. Center24×24, fixed4-pixel surround gives32×32. Center background RGB192; covered shape RGB64; alpha255 everywhere. Render each center pixel from4×4 regularly spaced subpixel centers and average the sixteen binary coverage samples: byte `192-8*coveredCount`, identical R/G/B.
- A family has center(cx,cy), half-lengthL, half-thicknessT, radiusR and rotation theta. In that exact draw order sample cx,cy uniformly[11,13), L[7,9), T[1.5,2.5), R[5,7), theta[-pi/36,pi/36). In inverse-rotated coordinates centered on(cx,cy), horizontal is abs(x)<=L and abs(y)<=T; vertical swaps axes; cross is their union; disk x²+y²<=R². Variant0 moves center(-.35,+.35), variant1(+.35,-.35), retaining every other parameter. No clipping/centering learned from labels.
- Train160 families/class (1280 images), development40/class (320), test80/class (640). Independent generator seeds train1103, development2207, test3301. Enumerate classes0..3 then family index then variant0,1. Assign the family to its split before creating either variant or any surround. Hash exact center RGB; if a proposed family produces a duplicate center image already emitted in any split or within the family, deterministically redraw the entire family, max100 attempts, else fail before fitting. Record accepted full parameters, family/variant IDs and raw hashes. Never split variants of one family across train/dev/test.
- Palette P0=(152,128,128), P1=(104,128,128), P2=(128,152,128), P3=(128,104,128); neutral=(128,128,128). Every palette color differs from neutral by squared RGB norm576. Border area448 means identical full-image RGB RMSE sqrt(84) byte units for every colored fixture. This proves equal encoded-pixel distortion, not equal perceptual effect.
- Training arms neutral, correlated, independent. Neutral always gray. Correlated assigns85% of families in each class its corresponding palette; remaining15% equally among other three. Independent assigns25% of families/class to each palette. Assignments use independent PCG64 permutations of each class's family indices with seed4409+splitIndex*100+class (splitIndex train0/dev1); both variants share assignment. For160 families:136 own+8 each other versus40 each; for40:34+2 each versus10 each. Total palette marginal counts are identical across correlated/independent arms. Center bytes and sample IDs/order are identical in all arms.
- Development diagnostics use the analogous frozen arms but are never used for hyperparameter selection. Test suites share the same640 held-out center rasters: neutral, matched palette Pclass, cyclic counterfactual P((class+1)%4), independent balanced palettes assigned20 families per palette/class using PCG64(5519+class). No worst-case palette is chosen after seeing a score.

Assignment determinism clarification before generation/fitting: initialize a fresh PCG64(seed) for each correlated and independent arm, so each uses the same family permutation rather than consuming a second RNG draw. Correlated palette blocks place the own-class palette first, followed by the other palette indices in ascending order; independent blocks use palette order0,1,2,3. The held-out independent assignment likewise uses a fresh generator for its specified seed. These conventions are explicit fields in protocol.json.

### Hash and manifest freeze recipes

It is not evolving Markdown. Parser rejects duplicate keys; producer/oracle compare every setting to this frozen contract before fitting. No CLI hyperparameter overrides in protocol v1.

Relevant production experiment logic stays in these files; introducing another code file requires root review and an amended fingerprint list before manifest freeze. No imported project helpers or opaque pickled model code. Dependency/native numeric versions are separately recorded in environment.
