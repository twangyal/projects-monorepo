# Whole-clip timing shift — #272

The existing cue editor now offers a collapsed signed-seconds utility for shifting all current cues. A pure detached proposal first validates the complete existing graph and offset, translates both endpoints without clipping or rounding, and validates the complete result. Invalid requests preserve raw fields, current cues, pending playback/import review and Undo/Redo. Zero and changes below floating-point resolution are refused rather than claiming a nonexistent edit.

A successful action explicitly retires practice, import review, timing capture and timeline gestures before mutation. It captures exact previous numeric spellings through the established draft snapshot and records one unsaved history edit. Literal Unicode words, title and unapplied pasted words are retained. Save, word highlighting, SRT/video exports and archives consume the ordinary corrected cues; no backend/schema/model/dependency/workflow changes are needed. The offset is session-only utility state and resets after successfully opening a different clip.

Unit cases cover detached positive/negative proposals, exact endpoints, invalid offsets/current graphs, out-of-range refusal and no-op resolution. Native coverage exercises main editing, prior numeric spelling, title/paste history, saved/reloaded SRT, refusal with native playback/pending SRT review, successful retirement, phone keyboard use and invalid drafts. [The integration receipt](../../../docs/2026-10-16-karaoke-timing-shift-integration.md) retains exact verification, failures and review.

This utility applies one numeric offset; it does not detect a delay, compensate physical playback/input latency or measure real-song alignment/correction effort. Karaoke remains ACTIVE, with #241 unchanged.
