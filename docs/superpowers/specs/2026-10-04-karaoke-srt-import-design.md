# Karaoke Studio: reviewed timed-lyrics import (#105)

## Purpose and scope

Import existing timed lyrics into a selected local clip without retyping or retiming them. Read a local SRT File, validate all cues, review the complete result, explicitly replace the current cues as one unsaved edit, correct timing with the existing waveform, and use Save lyrics. No new backend endpoint, dependency, inference, automatic alignment, media processing or quota change is required. Preserve the title, audio, selected clip and unapplied pasted words. Existing archive, video and SRT exports use the saved revision as before.

## Frozen input contract

- Pure `parseSrt(bytes: Uint8Array, duration: number): Cue[]` in `src/srt.ts`; export `MAX_SRT_BYTES = 128 * 1024`. Native File size is checked before reading and the parser independently checks actual bytes. Empty/oversized files fail. Use fatal UTF-8 decoding, admit one optional leading UTF-8 BOM, reject further BOMs used as syntax. No decoding replacement characters introduced by the reader.
- Normalize CRLF to LF; reject bare CR. Blocks may be separated/surrounded by empty or ASCII-space/tab-only lines. Each block has a contiguous canonical decimal number starting at 1 (no leading zeros), one exact `HH:MM:SS,mmm --> HH:MM:SS,mmm` line with two hour digits, minute/second fields 00–59 and three millisecond digits, and one or more nonblank text lines. No timestamp settings, VTT header, comments, omitted indices, dot fractions or permissive repairs.
- Preserve lyric text, spacing and Unicode code points exactly, joining multiline text with LF. Blank/space-tab-only lines are block separators and cannot represent an internal blank lyric line. Reject C0 controls except tab and LF, DEL, NEL and Unicode line/paragraph separators so server SRT splitlines cannot silently change admitted text. Reject any other text line consisting only of Python-style Unicode whitespace (for example NBSP), because the existing exporter would drop it; meaningful lines containing that whitespace remain exact. The existing Unicode/NUL/surrogate and nonempty checks still apply.
- Reject raw `<` and `>` with guidance to use plain text or `&lt;`/`&gt;`; never strip or evaluate markup. Decode only `&amp;`, `&lt;` and `&gt;` in a single pass, matching the existing server's exported escaping. Other ampersand sequences remain literal. Escaped angle brackets become literal text, never DOM markup. Count limits after this single decode. Document this supported subset explicitly.
- At least one cue; at most 200 cues, 240 Unicode code points per cue and 20,000 total lyric code points including preserved intra-cue newlines. Use existing `validateCues` against the selected clip's actual duration (1–300 seconds), ordered positive intervals, no overlap, gaps and exact adjacency admitted. Integer millisecond timestamps are converted to seconds once; never round existing unrelated timing values or clamp imports.
- Parse the entire file before showing a successful review. Errors identify the relevant cue/format where practical. No partial admission or silent text/time normalization beyond the declared BOM/line-ending/entity rules.

## UI and ownership

Add a visibly labeled **Import timed lyrics (SRT)** native File control (`#srt-file`) with the 128 KiB and plain-text subset guidance. Use an independent status (`#srt-status`) and full review region (`#srt-review`) containing filename, selected target clip, cue count, first/last times and every cue's exact millisecond times/text (`#srt-review-list`). Use textContent/textarea values, never imported innerHTML. Render existing cue text with textareas so multiline values remain editable and exact; update all busy/query/type handling consistently.

Review has explicit **Replace lyric cues** (`#srt-apply`) and **Cancel lyric import** (`#srt-cancel`) controls, with a clear statement that the selected clip's current cues will be replaced only in memory; title and pasted words are kept, and Save remains manual. No additional confirmation is necessary after this complete review and explicit action. Pending reads also expose Cancel. Choosing a newer File supersedes an older pending read/review.

Capture File operation identity, selected project ID, loaded project generation and monotonic edit generation. A changed-back edit still invalidates the review. Retire pending reads/reviews on current editor input, committed waveform change/gesture start, Undo/Redo, clip-open intent, save or media-job intent, deletion, newer File, cancellation and pagehide. Recheck ownership and allowed UI state at every asynchronous completion and before application. Retiring never changes the editor, server revision, undo/redo, audio position or existing raw fields. Unknown late completions cannot show stale errors or hide a newer review. Bound aggregate File read/parse/review-admission time to 10 seconds; cancellation/deadline ignores late File completion. No repeated timer polling and no server request from reading, reviewing or applying SRT.

Staging/cancel/error/status updates preserve editor nodes, focus/caret and raw spelling. Explicit application cancels a gesture, records exactly one fresh history step, replaces only cues and clears the review. Preserve title and pastedText/pastedDirty exactly (an existing unapplied paste still blocks Save with truthful guidance). Undo restores the previous cues, raw numeric draft spellings, title and paste; Redo restores imported values. Extend the existing bounded history snapshot only as needed to preserve raw numeric spelling; never make raw spelling define numeric equality or lose existing fractional precision. A successful Save retains existing history-reset semantics. A failed/conflicting Save keeps imported edits available.
