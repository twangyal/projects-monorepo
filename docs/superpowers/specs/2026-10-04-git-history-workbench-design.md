# Git History local browser workbench

Issue #52. The user authorizes autonomous implementation; this contract must receive independent review before implementation. Existing CLI/report behavior and the optional parser contract remain compatible. Gaze Nav and catalog #8 are excluded.

## Outcome and architecture

A developer runs `git-history serve --repo /absolute/repository` and opens the printed loopback URL. The browser discovers committed candidates, displays an immutable revision, shows numbered committed source, selects a function or 1–200 lines, and presents the existing evidence report with actual HTML/JSON downloads. Supplied context stays explicitly unverified. No repository execution, checkout, writes, source fetching or generated intent.

Use Python 3.11+ standard library HTTP and static vanilla HTML/CSS/JavaScript shipped inside the Python wheel. No runtime web framework, Node build or external assets. Python/manual selections remain dependency-free; the existing extra enables JS/TS. Development-only Playwright tests use Node, consistent with the monorepo.

`serve` requires `--repo`; `--port` defaults to 0 (OS-assigned), accepts 0–65535, binds only IPv4 127.0.0.1, and has no host override. Validate/normalize the configured repository at startup with the existing safe repository resolver, without requiring an unfiltered file catalog to succeed. Use initial HEAD; users can explicitly discover another ref. A fresh 256-bit capability appears only in the printed URL fragment. Browser code removes it from the address bar immediately and holds it only in memory. Reload requires reopening the original terminal URL. No browser storage, cookies, CORS, telemetry or access logs. Do not echo credentials, full request data or inspected content in unexpected errors.

## HTTP and job contract

Serve only `/`, `/workbench.js`, `/workbench.css`; no filesystem path routing. Validate exact Host `127.0.0.1:<actual port>` before all routes (no localhost/alternate host). All API calls are POST, require exact same-origin Origin plus `X-Git-History-Token`, and accept only UTF-8 application/json. Reject missing/duplicate/conflicting framing, transfer encoding, oversized input, unknown fields, nonfinite/duplicate-key JSON, wrong scalar types and unsupported methods. Request body cap 2 MiB; an absolute 5-second deadline across request headers and body (not only socket inactivity); authenticate/validate headers before reading bodies; close each connection. Cap simultaneous HTTP handler threads at eight; refuse excess rather than queue unbounded threads. Reject cross-site fetch metadata when supplied. No token in API URLs or logs. Standard no-store, nosniff, no-referrer, restrictive CSP and framing protection apply to every reply.

API responses use `{error: string}` for rejected requests. Job result shapes below are frozen for UI/server/test owners:

- `POST /api/session {}` → `{repo_name: string}`.
- `POST /api/jobs {operation, args}` → HTTP 202 `{id: string}`. One active job globally; reject overlapping creation with 409. A new accepted job replaces the previous completed result. IDs are fresh opaque random values.
- `POST /api/result {id}` → `{id, state: 'pending'|'complete'|'error'|'cancelled', result?, error?}`. Unknown/expired IDs return 404. Read result does not consume it.
- `POST /api/cancel {id}` → `{id, state: 'cancelling'|'complete'|'error'|'cancelled'}`. Cancellation does not free the busy slot until cleanup finishes. A completed result remains usable; cancel races do not change a previously published complete job.

Operations and exact args/results:

- `files`: `{ref, directory, language}` → existing FileCatalog object. Ref ≤1024 UTF-8 bytes; directory ≤4096. Language all/python/javascript/typescript. Discovery resolves the ref exactly once.
- `source`: `{revision, path}` → `{repo_name, revision, requested_ref, path, source, line_count}` from a new public bounded committed-source API. All post-discovery revisions are full lowercase 40/64 hex IDs. Path ≤4096 UTF-8 bytes, exact relative text; existing validation rejects traversal/symlinks/non-UTF8/NUL/oversized blobs. Original physical LF line count, no invented trailing line.
- `functions`: `{revision, path}` → existing FunctionCatalog. Parser errors leave manual selection available.
- `report`: `{revision, path, selection, max_commits, context}`. Selection is exactly `{start, end}` (integers) or `{function}` (exact nonempty name ≤8192 UTF-8 bytes); max_commits integer 1–50; context null or raw JSON string ≤256 KiB UTF-8. Result `{html, json}` contains exact existing rendered strings from the same Report and supplied-context parse. Browser JSON input never names a server-side file. Add a public bytes/text context parser shared with the existing bounded file loader; keep both envelopes and validation unchanged.

Each rendered report remains ≤8 MiB. Each serialized API response is capped at 32 MiB, including escaped strings. No unbounded job history, request queue, result files or source cache. Jobs run in one supervised worker thread; cap all Git/native subprocess work with a shared 45-second monotonic operation deadline, cancellation event and 32 MiB aggregate combined subprocess-output cap. Charge stdout/stderr bytes during draining before appending, across all Git/parser calls in a job; the existing individual command/parser caps still apply. Add an optional context-local work budget to the subprocess loops, inert for existing CLI commands. Check cancellation/deadline before spawning, while draining/waiting (≤100 ms polling), between stages and before publishing. Existing process-group kill/reap paths clean up every directly supervised Git/native child; do not kill only an outer process and orphan new-session children. Bounded in-process parsing/rendering checks the budget before/after, so cancellation is cooperative during those bounded stages, not a hard real-time wall guarantee. Shutdown cancels and joins the worker and closes listeners; no child remains active. Timeout/cancel must not degrade into a successful partial report through optional-history warnings. Budget exceptions must be outside GitError/ReaderError/NativeParserError catch hierarchies. Include process wait after EOF in ≤100 ms cancellation polling. While the scoped workbench budget is active, Python AST/tokenization must also use a resource-limited standard-library subprocess (same 5-second/512 MiB/CPU/output limits as native parsing); keep ordinary CLI Python behavior and optional JS/TS API acceptance unchanged. Reuse the supervisor through a distinct parse_python_functions_isolated entry and separate worker modes, avoiding a recursive subprocess in the child. A valid 512 KiB AST probe already exceeded a 256 MiB process limit in independent review; source size alone does not bound parser memory.

## Interface and lifecycle

One clear screen: repository/ref controls; directory/language discovery; paginated file candidates; current immutable revision/path; committed numbered source with manual range controls and optional function discovery; supplied-context file/clear; evidence report and two downloads. Use textContent for source/metadata, never treat it as markup. Show file paths with visibly escaped control characters while retaining exact raw values for requests. Source uses LF-delimited physical lines and a bounded page (100 rows); files/functions paginate at 50. Bound local filtering/rendering and show catalog omissions/limits. A 512 KiB file with many lines must not produce a giant DOM. Functions longer than 200 lines or ambiguous names offer listed manual ranges; do not pretend named selection succeeds. Very long names can use manual selection.

Selection/ref/path/context/limit changes invalidate displayed report downloads for that selection; preserving a previous report on a failed request must clearly identify its original selection. Preserve typed inputs and imported context through asynchronous redraws and recoverable failures. Explicit source-path entry supports manual source inspection outside the candidate suffix list. Invalid form text remains visible for correction. A missing/expired session offers terminal reopening guidance without trying unauthenticated work.

Use a generation guard and job cancellation for all replacement work. Stop invalidates normal result publication and requests server cancellation; retain terminal-state cleanup polling until the busy slot is actually released before starting replacement work. A stale response cannot replace newer source/report or recreate download URLs. Revoke Blob URLs on replacement/teardown. No automatic report generation on every keystroke. Jobs expose accessible busy/status text with a Stop control; the user can still correct draft controls. Switching discovered snapshots must never mix an old file/function/source with a new ref.

Render existing report HTML in an iframe sandbox without scripts or same-origin access. Permit allow-popups and allow-popups-to-escape-sandbox for the renderer’s existing explicit target=_blank evidence links; preserve internal anchors. Parent CSP must allow the embedded report’s inline styles, while script policy stays self-only and the iframe forbids script execution. HTML/JSON downloads are the exact rendered strings, not DOM reserialization. Downloads contain private source just as CLI reports do; show concise local-only/share-carefully guidance. Responsive desktop/mobile layout, labeled forms, native buttons, keyboard navigation, visible focus, live error/status and iframe title are required.
