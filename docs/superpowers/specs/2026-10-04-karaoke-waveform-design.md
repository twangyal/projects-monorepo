# Karaoke waveform timing workbench

Issue #54 · `apps/karaoke-studio` · Astra. The user's autonomous authorization covers design and implementation. Gaze Nav and catalog #8 are excluded. Existing project JSON, service routes, separation and export formats remain compatible.

## Outcome

Make supplied lyrics practical to time across a complete song: show the actual original-audio amplitude, seek and zoom, select a lyric cue, adjust either boundary reversibly, save explicitly, and export the saved revision. The waveform is always labeled **Original audio waveform**, even while listening to vocals or backing. It does not identify words, singing, or automatic alignment.

## Signal and resource contract

Read the existing same-origin `/api/projects/{id}/audio/original` in a fresh module worker. Validate a 32-character lowercase hexadecimal project ID and finite expected duration in [1,300]; construct the URL internally. Fetch with no cache and redirects rejected. No whole-response `arrayBuffer`, `Blob`, `decodeAudioData`, full PCM copy or main-thread audio decoding. Process incoming data incrementally in slices of at most 64 KiB, checking the deadline between slices. A 30-second whole-operation deadline in the worker and owning UI bounds stalled reads or computation; abort/terminate on stop, replacement or teardown. Progress reflects actual decoded frames, at most ten messages per second. Error messages are bounded and actionable, never raw response bodies.

Require little-endian RIFF/WAVE with exact container length, at most 52,924,096 bytes (300 seconds of stereo PCM16 plus 4 KiB overhead). Walk chunk headers and odd-byte padding incrementally; reject crossing the declared end, duplicate format/data chunks, missing chunks, truncation, trailing bytes and unsupported formats. Exactly one `fmt ` precedes exactly one `data`: PCM format 1, two channels, 44,100 Hz, 176,400 bytes/second, block alignment 4, 16 bits. Accept canonical 16-byte format or 18-byte format with zero extension size. Unknown chunks are skipped without allocation; aggregate non-data overhead is at most 4,096 bytes and at most 512 chunks. Data length must be frame-aligned and contain 44,100–13,230,000 frames. Require `abs(frameCount - expectedDuration * 44100) <= 1` (with only machine-roundoff tolerance); do not use the compressed-input metadata allowance or silently trim.

Pure `waveform.ts` owns `Pcm16PeakReducer` and a streaming `NormalizedWavPeaks` parser. Both expose `push(Uint8Array)` and `finish()`; the latter takes expected duration. Final output `WaveformPeaks` contains `frameCount`, `sampleRate:44100`, `binFrames:441`, `minima:Int16Array`, `maxima:Int16Array`. Bin i covers `[i*441, min((i+1)*441,N))`. Preserve minimum and maximum across **both** channels, including opposite phase; initialize to 32767/-32768, never zero or channel averaging. Handle arbitrary byte splits with at most three carried sample bytes. Keep only at most 30,000 min/max pairs (120,000 bytes). The final partial bin uses real frames only, and the authoritative duration is N/44100, not bin count times 10ms. Transfer only the final small arrays after complete EOF validation. Drawing divides by32768 and aggregates all bins intersecting a screen column, so short impulses cannot vanish by subsampling.

`waveform.worker.ts` takes one `{projectId,duration}` request and reports `{type:'progress',framesRead,totalFrames}`, `{type:'ready',peaks}`, or `{type:'error',message}`. A worker handles only one request. The timeline controller owns one worker and its deadline; callbacks must verify worker identity and captured project generation. Stop/failure leaves numeric editing and audio playback available with Retry waveform. Changing the audition stem does not reload the original waveform. Completed peaks are transient, never saved as sidecars or browser storage.

## View and draft ownership

`timeline.ts` owns the worker, canvases, selection, view window and provisional gestures. `main.ts` continues to own audio playback, mutable lyric drafts, history, saved revision and exports. Public `mountTimeline(root, callbacks)` returns a controller with editor update, playback update, select cue, cancellation and teardown methods. Freeze exact TypeScript interfaces before dependent implementation; use separate editor/playback updates so native time updates do not cancel an edit.

Show a full-song overview and detail window with 60/15/5-second choices, previous/next window and Center on playhead. Window stays fixed during playback and gestures. Overview/detail clicks seek without autoplay. Supply a native keyboard-accessible seek range. Visible cue spans, a native cue selector and a row action select a cue and center the detail window. Selection, seek and zoom do not dirty the project. Bound labels even when a user has entered a megabyte of invalid text. Canvas dimensions/DPR and processing remain bounded; mobile at390px must not overflow.

Start/end handles use separate lanes and at least44px touch targets; accessible slider names, numerical values and focus styles accompany pointer gestures. Arrow keys adjust10ms; Shift-arrow100ms. A held key with repeats is one gesture until keyup. Pointer movement quantizes the **delta from the original boundary** in10ms increments, preserving existing non-grid precision. Outer edges can reach exactly0 or exact project duration. Never silently clamp against adjacent cues: overlapping or zero-length results are rejected. Existing nonedited cue numbers/text remain exact.

`timing.ts` supplies pure timing validity, bounded view/time coordinate helpers and boundary proposal validation. Validation concerns timing only, so an invalid title/text draft remains intact while timing can be adjusted. Any invalid numeric cue timing disables handles while seek/zoom continue. Adjacency and gaps are valid; all cue intervals remain ordered, finite, nonempty and within the project duration.

Provisional motion stays outside `working.cues` and `LyricHistory`. Capture project ID/generation, a separate edit generation, cue index, boundary and original value. At successful release, root integration rechecks identity/generations, availability and timing validity, mutates only that existing cue's boundary, patches only its existing numeric input and calls `changed(null)` once. No-op, invalid or cancelled gestures record nothing and preserve redo. End a typing history group before starting a gesture. Undo restores original numeric values exactly.

Never call `renderCues()` for waveform progress, load, seek, selection, zoom, provisional edits or cancellation: it replaces inputs and rounds their display, destroying raw browser drafts. Successful waveform commits also avoid a full cue render. Preserve focused inputs, pasted drafts, invalid text, title, and untouched numeric spelling. Existing explicit Save and server revision invalidation remain authoritative.

Escape, pointercancel, lost capture, window blur, viewport/canvas resize, view/selection/track changes, Stop/retry, a competing edit, undo/redo, save initiation, project open/replacement/deletion and teardown cancel gestures without restoring old state over new edits. Busy editor state disables boundary editing, not ordinary playback. Starting project navigation stops pending waveform work; a failed project fetch retains the current draft and completed peaks (or retry state), while a successful replacement clears old peaks before requesting its source. Late worker messages and pointer/key releases must be inert. Audio metadata callbacks capture media-load and project identity too; an old track's seek/play intent cannot reach a newer project.

## Frozen implementation interfaces

The reducers expose readonly `framesRead` and `totalFrames`; the WAV parser reports total0 until a valid data header. The lower-level PCM reducer accepts1–13,230,000 frames for tiny independent fixtures; normalized WAV retains the1-second minimum. Request/reply types live in `waveform.ts`, not the executable worker module.

`timing.ts`: `CueBoundary = 'start'|'end'`, `TimeWindow = {start:number,end:number}`, `timingError(cues:readonly Cue[],duration:number):string|null`, `proposeBoundary(cues,duration,index,boundary,value):Cue[]` (detached objects, no mutation), `quantizeBoundaryDelta(original,deltaSeconds,duration):number` (Math.round ticks, ties toward positive infinity, exact zero delta preserves original), `timeWindow(duration,span:5|15|60,center):TimeWindow`, `timeToPixel(time,window,width):number`, `pixelToTime(x,window,width):number`. Coordinate helpers clamp and reject nonfinite/invalid geometry; proposals validate current and final timing arrays.

`TimelineEditor = {projectId,projectGeneration,editGeneration,duration,cues:readonly Cue[],busy:boolean}`; `BoundaryCommit = {projectId,projectGeneration,editGeneration,cueIndex,boundary,before,after}`. `mountTimeline(root,{onSeek(time),onSelectCue(index),onGestureStart():boolean,onCommitBoundary(change):boolean})` returns `{setEditor(editor:TimelineEditor|null),setPlayback(time),selectCue(index),cancelGesture(),stopWaveform(),destroy()}`. The editor's project generation identifies the last **successfully loaded** project; main keeps it separate from the in-flight navigation request counter so failed navigation can retain completed peaks. `stopWaveform` cancels gestures/pending worker while retaining completed peaks. Main rechecks all commit identity fields and timing availability before mutation; only the affected existing input value is patched.
